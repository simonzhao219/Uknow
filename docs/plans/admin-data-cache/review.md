### P1

**P1-1〔§2.5、§2.4、§4.3、§6 Q1〕「已確認」的定義與閘門覆蓋面不足，與規劃自己的驗收矛盾**
- 來源：系統 #2（P1）；架構 #3 後半（建議同一解）；需求 P2-1（Q1 漏列金額，P2〔需人工裁決〕）。
- (a) 作業面板只看 `isFromCache`：同掛載內換回已載入過的篩選、或寫入後重讀時為 false，未確認的那筆照樣顯示——與 §1.2-2「更新完成前作業面板顯示骨架」不一致。
- (b) `stats.pendingAmount`（待匯款總額）從快取顯示、只降透明度；它是「admin 開網銀前要對的數字」（`20260802000006_withdrawal_stats.sql:5-7`、`WithdrawalManagement.tsx:643-644`）。Q1 只討論件數。
- (c) 錯誤態只換掉列表卡的內容；作業面板、統計、複製鈕不在被替換的區塊（`:613-710`），仍顯示舊值——「確認失敗就不再顯示」不成立。
- (d) 錯誤後按「重試」：§2.2 表寫「有本鍵資料→保留列表」，舊列會重新出現，與 §4.1「錯誤後重試出骨架」、§1.2-3 相反。
- → 以單一導出旗標 `isConfirmed`（目前鍵的最新請求已成功落地、其後無新請求、無錯誤）取代各頁自組的 `isLoading||isRefreshing`／`isFromCache`；面板、`pendingAmount`、複製、勾選、寫入鈕、CSV 全吃它；錯誤態恆為 false、重試走骨架。Q1 拆開：件數可降透明度，金額比照作業面板。

**P1-2〔§2.2 狀態表、§2.7〕旗標沒有與序號綁定，閘門可能在最新重讀還在途時被舊請求打開**
- 來源：系統 #3。
- 現行 `reload` 的 `finally { setIsLoading(false) }` 對每個請求無條件執行（`usePagedList.ts:54-56`）；沿用的話，被作廢的舊重讀一結算就清旗標。例：Slow 3G 下連換篩選 A→B→C（篩選只在匯出中停用，`:734`），C 命中快取，B 的結算清掉旗標，C 未確認的列寫入鈕即可按。
- 表也沒定義掛載第一個 render 與換鍵那個 render 的旗標；若等 effect 才設，會有一個「有快取列、閘門全開」的 render。
- → 旗標由「最新 ticket 在途／已落地」導出，被作廢的結算不得改任何旗標（含 `isLoadingMore`）；第一個 render 與換鍵 render 同步導出；階段 1 補「連換鍵 A→B→C」「命中快取的第一個 render 寫入鈕即停用」。

**P1-3〔§2.2 loadMore 列、§2.7〕更新中仍可「載入更多」，序號擋不住這個方向**
- 來源：系統 #4、架構 #4、UI/UX #2（皆 P1）。
- 載入更多只在 `!isLoading` 時渲染（`WithdrawalManagement.tsx:938-944`、`MemberManagement.tsx:638-650`），背景更新中可按。loadMore 帶 `peek()`＝與重讀同號：重讀先落地換成新第一頁後，loadMore 仍是「最新」，以舊 offset 的頁尾接上新第一頁——重複列、漏列、重複 React key、「已顯示 N / total」錯；`:750-751` 的註解自己點名「重複或錯位的列不能出現」。
- → 重讀在途時 hook 拒絕 `loadMore`、UI 鈕同步停用（`hasMore` 對 UI 為 false）；重讀落地時遞增代數作廢在途的 loadMore；階段 1、4、5 各補「更新中按載入更多」。

**P1-4〔§2.5、階段 4〕「換一批資料就清掉勾選」的安全不變式改走 `usePagedList` 後失去歸屬**

**P1-5〔§0、§2.5、§7〕「等於強制同步 revalidate」「過期資料永遠不會成為寫入依據」宣稱過強；閘門是 prompt 1(b) 兩選項之外的第三案**

### P2

**P2-1〔§2.3、§2.6、§2.7〕失效＝刪鍵，三種併發沒處理**
- 來源：系統 #7、需求 P2-7。
- (i) 失效前送出、失效後才落地的讀取：鍵已被刪、沒有較新條目可比，舊列被復活；(ii) 寫入在途時切走分頁，若後續被「已卸載就略過」包住，`invalidate` 不會執行；(iii) 網路錯誤／逾時（結果不明、可能已提交）只重讀、不失效，`markChanged` 也只在成功時呼叫。
- → `invalidate` 記失效戳記（per-key fence），`write` 丟棄更舊者；規定 `invalidate`／`markChanged` 卸載後仍執行；非 4xx 驗證錯誤的失敗一併執行；各補一條測試。

**P2-2〔§2.3 生命週期〕撤權時後端回 403 不觸發任何清除**
- 來源：系統 #8。
- 「權限被撤→`isAdmin` 變 false→卸載」只在視窗 focus／visibilitychange 重抓 `/profile` 時成立（`App.tsx:269-276`）；`apiClient.ts:191-209` 只對 401 處理。持續停在後台的被撤管理員切分頁時會先看到快取 PII，重讀 403 才進錯誤態，條目還留著。
- → hook 對 401／403 觸發整體失效事件（表加 `accessLost`）；§2.3 如實寫「撤權最遲到下一次 focus 才卸載」；補一條測試。

**P2-3〔§2.5「讀取入口不停用」〕「查看證件／歷史」在未確認窗口可開，對話框持有點擊當下的列快照**
- 來源：系統 #9、架構 #19（P2）；需求 P2-6（P2〔需人工裁決〕）。

- → 兩個對話框在未確認時停用，或改持 id、由最新列解析；並把「哪些顯示面算寫入依據」寫成一條統一規則。

**P2-4〔§2.2、§2.4〕空結果也被快取，「目前沒有提領申請」可能是過期的肯定句**
- 來源：系統 #10（P2〔政策需人工裁決〕）、UI/UX #9。
