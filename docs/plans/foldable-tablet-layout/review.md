## 發現清單

### P1
1. [P1]〔§4 首頁卡片、§5 階段 1〕（系統）規劃寫「`ListingLink` 加 `block h-full`（桌面卡片傳 className）」，但桌面呼叫處（`HomePage.tsx` ≈1174）目前沒傳 className → 建議改成「桌面呼叫處傳 `className="block h-full"`、`ListingLink` 不動」，vitest 斷言掛在桌面卡片的 `<a>` 與 `Card` 上。
2. [P1]〔§4 首頁卡片、§5 階段 1〕（UI/UX）等高機制描述有誤：grid item 預設 stretch，真正沒撐滿的是 `<Card>`；只加 `h-full` 內容仍靠上、地區列底部不齊；`min-h-[2.5rem]` 綁死行高 → 建議 `CardContent` 改 `flex flex-col h-full`、地區列 `mt-auto`（或描述 `flex-1`），沿用手機版 `block h-full`＋`Card h-full` 模式；探針同時量卡片底邊與地區列 `top`。
3. [P1]〔§5 階段 2〕（架構）`e2e/test_public_skeleton_layout.py` 第 43 行以 `className.includes('lg:grid-cols-2')` 找格線（75、172 行訊息亦寫死），改 class 後探針回 null、測試因「找不到格線」而紅；且只參數化 `[375, 1280]` → 階段 2 明列改探針選擇器（`md:grid-cols-2` 或 `data-browse-content` 錨點）、寬度擴成 `[375, 768, 884, 1280]`，與 class 同 commit 改。
4. [P1]〔§4 目標視窗、§5 階段 2〕（UI/UX）視窗矩陣缺斷點邊界 → 加 767×1024（單欄）、1023×768（詳情雙欄、首頁 2 欄）必測；首頁 `hidden md:grid`／`md:hidden` 在 767／768 各驗只有一套可見；841×701 驗首屏看得到名稱／類別／地區。
5. [P1]〔§1 驗收 1 vs §5 階段 2〕（需求）驗收寫「首屏同時看到名稱／類別／地區」，探針只驗名稱與兩欄 `top` 相同 → 在 841×701、768×1024、884×1104 斷言三者 `getBoundingClientRect().bottom ≤ viewport 高度`。
6. [P1]〔§6 Q2、§5〕（需求）業主明列「首頁卡片欄數」，Q2 建議維持 2 欄且自述需業主認可，但無階段承接 → Q2 標「開工前需業主裁決」或階段 3 列明以 884／841 截圖交業主確認；每卡寬度依據（2 欄約 400px、3 欄約 260px）寫進規劃書。
