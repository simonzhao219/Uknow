規劃書 v2 已完成、四視角審查已完成（`./review.md`），**尚未開工，停在人審**。

帶著 P0 進實作。

1. `withdrawal_events` 新表沒有 RLS/GRANT（違反本專案零例外的建表慣例）

   範圍且規格書無依據；審查者提出「不阻擋」的更小替代方案

P0-1 與 P0-2 是純技術修訂，改 plan 即可。**P0-3 需要需求方裁決**——它會連帶
消解數條 P1（四契約、dialog 步驟數、backfill 急迫性、首次提領新等待、§5.3
例外）。

審查期間需求方已裁決：證件審核 SLA 3 個工作天、詳情面板遮罩、交易序號選填、

- web session 的預設分支是 `claude/*`，與 CLAUDE.md「真的要走三段式流程時，
  自己切一個 `feature/<slug>` 分支」相衝——本 session 被平台綁定推送分支，
  切 `feature/*` 會推不上去。三段式因此在 `claude/*` 上執行，規劃檔守衛全程
  不生效（流程靠自律而非機械把關）。
- `/review-plan` 派出的 reviewer subagent **不會在 session 恢復後存活**，
  結果直接遺失且無任何痕跡（沒有 review.md、沒有錯誤）。長規劃若中途被打斷，
  審查等於白跑一次。或許 review.md 應該由每個 subagent 各自落檔後再彙整，
  而不是全部彙整完才寫檔。
